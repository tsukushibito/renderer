# Sashiko のキャラクターアニメーション設計

固定 tick でゲームに必要な動きを確定し、描画時には複数のビューとパスが同じ変形結果を共有する。CPU の評価単位はキャラクターのポーズ、GPU の変形単位はポーズを適用したメッシュの LOD とする。これにより、防具を追加しても歩行の評価は一度で済み、同じ防具を深度・影・本描画に使うときも頂点変形を共有できる。

CPU ポーズ評価は単精度で、整数 tick・ルート並進の倍精度積算から独立している。読込時のバインド逆行列・ローカル姿勢復元と試験用の参照計算は倍精度を使い、表示用データの変換時に有限性・スケール・回転を確認する。Survivor の群衆は 0・13・26・39 tick のうち実際に使う位相の収録パレットを参照し、同じ位相の個体は変形済み頂点を共有する。通常の接地影では CPU、キャラクターを影マップにも描く場合は Compute を既定とする。

`PoseBatch` は骨格、全身または部分ボーン集合、出力件数の上限を準備時に固定する。呼び出し元が確定した表示サンプルを入力順に受け、4 件ごとに同じボーンの 4 ポーズを SIMD レーンへ配置する。平行移動・スケール・回転の合成と親子行列積をまとめ、親を先に評価する。球面補間の重みは各レーンの角度から求める。残り 1〜3 件は逐次評価する。メモリの再確保やイベントの消費は行わない。`evaluate_scoped` は共通ジョブ実行器に独立した SIMD グループを渡し、評価完了後の出力を返す。並列評価では各グループが自分の出力行列の領域に階層計算の中間値を保持してから展開する。1 並列、8 姿勢未満、または評価対象の関節数と姿勢数の積が 128 以下なら既存の逐次 SIMD 経路を使う。[精度と採用時の計測](../verification/current.md#animation-cpu)

メッシュ用の `PaletteBatch` は、クリップ番号と tick を指定した収録フレーム、正規化位相で選んだ収録フレーム、呼び出し元が解決した `PoseSample` を入力順に返す。スキンとクリップ範囲は読込時に検査し、モデルのスキンは読み取り専用とする。収録パレットはモデルとバッチで共有する。合成数をゼロで準備したバッチは姿勢用の作業領域を持たず、旧形式のスキンにも使える。合成用のローカル姿勢は `prepare_pose_clip` で必要なクリップだけ取り出す。同じサンプルを複数の要求から参照できる。16 サンプル以上かつ関節数との積が 992 以上のときは共有チームで階層合成とパレット変換を行う。[計測結果](../verification/current.md#animation-palette-jobs)

`Playback::advance_to` とヘッドレス用の `ClipTimeline::interval` は前回を除く今回までのイベントとルート並進を返す。容量不足なら出力と時刻を保持する。ゼロフレームのイベントは次の周回境界で発行する。クロスフェードでは遷移先のイベントを取り、並進差分を各固定 tick の中央の重みで混合する。両曲線の停止以降は積算を終える。`is_finished` は単発クリップの最終フレームの表示期間を含み、`is_transitioning` で遷移の終了を独立して照会できる。

表示は `Clip::sample_at` で収録フレームを保持し、`interpolated_at` または `sample_phase` で隣接ローカル TRS を補間する。`BlendLine` と `BlendSpace` はサンプル番号と重みを返す。2D は作者指定の三角形の重心座標を使い、領域外では最寄りの辺へ投影する。`LocalBuffer::mix` に正の総和を持つ非負の重みを与え、入力順で最短弧回転を合成する。`overlay` は関節別マスクで上書きし、`additive` は参照姿勢からの並進差、回転差、スケール比を適用する。強さゼロの関節はベース姿勢を保持する。部分評価の行列は要求骨と祖先の分だけ確保し、骨番号の対応と親順序をバッチ内で共有する。

Survivor のプレイヤーは実移動速度 2〜4 m/s で walk と jog の重みと歩行周期を連続的に変える。停止中は位相を保持する。カタログの `tracks.sync_markers` はクリップ内で一意な接地位置の ID とフレームを記す。付属素材は ID 1・2 を walk の 20・60、jog の 14・42 フレームに割り当てる。対応する ID の間を線形に写し、接地は walk の `events` 内の足音 ID 1 を固定 tick ごとに一度消費する。対応する同期トラックがないときは正規化位相を共有し、重みが大きいクリップのイベントを採用する。jog を持たないモデルは walk を使う。録画のゲーム規則版は 2 で、録画に両方のタイムラインを保存する。ヘッドレス再生は録画に保存された接地時刻を使う。デスクトップの足音は各固定更新の `Events::footsteps` から効果音バスへ渡す。

### 評価基盤の契約

`Clip` は同じ骨格に結び付いた全関節のローカル TRS を各フレームに持つ。疎なトラックを取り込む際は cook または読込時に通常クリップの欠損をレスト姿勢、加算の欠損を変化なしとして解決する。実行時の `Skeleton` は親子関係と評価順を保持する。通常ブレンドの重み総和ゼロは入力エラーとし、静止姿勢を使う呼び出し側が明示的に選ぶ。モデル空間の関節姿勢はメッシュと独立なので、手の位置を調べるだけならパレット変換は不要である。

任意時刻の表示には副作用のないサンプリングを使う。現在の `Playback` は前向きの固定 tick で進み、遷移先を先頭から再生する。再生中のカーソルのシーク、速度変更、フェード中の再遷移は拡張事項である。シークを導入するときは、飛ばした区間のイベントと移動量を発生させず、新しい位置から次の固定更新を始める。現行の Root Motion は並進のみ。回転を使う全身動作を導入するときは、姿勢から抽出済みのローカル移動差分を周回順に合成し、ゲームが衝突解決後の移動量を確定する。

### 標準キャラクター制御の導入条件

継続的な移動入力と一度だけ届くアクション要求を別に扱う。ゲームが許可したアクション ID に対し、制御側がクリップ、部位マスク、スロット、優先度、中断可否を設定から解決する。最初の構成は上半身と全身を各1枠とする。同順位は先着を維持し、全身回避が上半身リロードを中断したら、ハンドルに中断結果を返す。見た目のフェード中も中断済みハンドルから装填通知を出さず、回避後の再開には新しい要求を要する。競合する要求は理由を付けて返す。

固定更新では再生位置・重みを確定し、代表ソースの移動イベントと採用するルート差分を一度だけ渡す。上半身アクションのマーカーは個別に扱う。全身姿勢の書き出しは任意とし、利用側が必要な関節だけを準備済み領域へ評価できるようにする。タイムラインだけのヘッドレス再生と群衆の収録パレット経路を保つ。出力容量が足りないときは、個体の全スロット・時刻・通知・移動差分を更新前に保ち、必要量を返す。

受け入れには、走行中の上半身リロードをフェード開始直後に全身回避で中断するシナリオを使う。脚の位相、装填通知の停止、回避移動の一度だけの適用を確認する。同じ入力を描画あり・なしで再生し、足音と位相を照合する。容量不足後の再試行結果は、初めから十分な容量で更新した結果と一致させる。

### Motion Matching の導入条件

検索は予測軌道と上半身合成前の移動姿勢履歴から、現在の区間の継続、指定クリップ・時刻への切替、候補なしを返す。検索しない tick も再生は進める。全身動作からの復帰時には履歴を再初期化する。標準移動と検索移動のどちらも同じ上半身アクションに接続でき、標準移動だけのビルドには検索コード・DB・個体別履歴が不要となる依存方向を保つ。

採否は同一素材・同一入力リプレイで判断する。急停止・方向転換の足滑りと切替の連続性を比較し、対象機の個体数で検索頻度、CPU 時間の p95、共有 DB と個体別履歴のサイズ、定常時のメモリ操作を測る。共通の制御インターフェースは二つの実装を接続してから決める。FSM、編集用グラフ、IK、圧縮や外部評価ライブラリの採用には個別の利用要件または計測を要する。

## CPU 評価と固定 tick

1. **入力を確定する。** ゲームは固定 tick ごとに入力を渡す。評価は進んだ時間区間から状態遷移、ルート移動差分、イベントを求める。ループ境界をまたぐ場合も区間ごとに拾い、描画の再試行で再消費しない。ワーカーは個体別の領域に書き、ゲームが tick、安定した個体 ID、クリップ内順序で結果を消費する。
2. **必要なボーンを決める。** 当たり判定用の手は画面外でも固定 tick で評価する。部分評価には対象ボーンの祖先と、IK などの制約が読むボーンを含める。遠景の表示用ポーズには頻度低減と補間を許し、ゲームのイベントと移動は固定 tick を維持する。
3. **個体間でジョブを配る。** 同じ骨格・評価プログラムの個体をまとめ、ホストの共通ジョブ実行器へ渡す。各ジョブは入力を共有し、出力を排他的に借りる。クリップを展開し、独立するトラックを SoA（成分ごとの配列）でまとめて補間し、ローカル姿勢をブレンドする。階層合成は親から子へ進める。個体間のバッチ分割で複数コアを利用する。実装済みの SIMD は同じ骨格の複数ポーズを対象とする。
4. **利用地点で待ち合わせる。** 物理は要求したゲーム用姿勢、Renderer は表示用姿勢の完了を待つ。少数個体には呼び出し元での逐次評価を用意し、ジョブ分割の閾値は骨数・層数とスケジューリング費を含めて測定する。

## GPU スキニングとマルチパス

Survivor のネイティブ版では `--character-shadows` でプレイヤーと敵を影マップにも描く。画面外の敵もキャスター候補に含める。経路を固定するには `--skinning cpu` または `--skinning compute` を指定する。影ありの既定値は4位相の転送量削減と複数パスでの頂点再利用を優先して選んだ。終盤500体の実測ではゲーム全体のフレーム時間は CPU 経路と同程度だった。直接の頂点シェーダー適用は独立した比較試験で評価する。

標準の描画経路では、登録前に `MeshData::with_compute_skin()` を呼ぶ。メッシュの版がバインド頂点・ウェイトの読み取り専用バッファを所有し、インデックスと同時に公開する。分割転送、差し替え、退役は既存のメッシュ登録と同じ寿命規則に従う。ポーズは関節パレットを保持する。フレーム内で同一ポーズ・版の出力を一度記録し、本描画・影・別ビューが同じ頂点を読む。単一の graphics キューで、Graph が転送、Compute 書き込み、頂点フェッチの依存を解決する。

標準パイプラインは各ビューでポーズの境界と版を読み、カメラ・更新対象のカスケード・矩形光源の影に使うオブジェクトを選ぶ。最初の描画要求で変形を記録し、後続ビューとパスから同じフレームの出力を参照する。履歴を再利用できる影だけが参照するポーズは変形を省く。アプリケーションが異なる LOD を選ぶときは、それぞれのメッシュとポーズを登録し、本描画専用は `casts_shadow = false`、影専用は `camera_visible = false` とする。カスタムパスは必要なオブジェクトで `SceneInput::import_mesh` を呼ぶ。変形の成立時点を遅らせても、パレット転送・Compute 書き込み・頂点フェッチ間の依存と GPU 完了後の回収は既存の Graph に従う。

ロード時に正のウェイトを持つバインド位置から各関節の AABB を作る。パレット更新時には各 AABB を関節変換して合併する。正規化した非負ウェイトによる補間結果は変換後の位置の凸包に含まれる。行列積・ウェイトの単精度丸めとサブノーマルのフラッシュ分を広げ、頂点ごとの走査を省く。位置計算の有限性を保証できない更新は、直前のパレット・境界・版を保持して失敗を返す。この境界は現在の線形ブレンドに適用する。

ホストが RenderGraph を組む場合は、ロード時に `MeshData::prepare_compute_skin` で正規化済みウェイトとバインド頂点をまとめ、`bind_bytes()` を GPU に一度転送する。各フレームに同時に必要な変形の数だけ `reserve_pose` で準備する。各ポーズの `add_pose` に常駐バッファの import とメッシュ用パレットを渡すと、モデル空間の PBR 頂点バッファを返す。同じメッシュ・LOD・ポーズを描く全パスでこのハンドルと元のインデックスを使う。カリング境界は呼び出し側が用意する。

最初の Compute 経路は既存 PBR 頂点 ABI に合わせ、位置・逆転置変換した法線・接線・接線の向き・UV を 48 B に書く。1ポーズごとのパレット転送は固定 12,288 B（最大128関節）。この上限は静的なシェーダーの読み取り範囲を保証する。入力は64頂点単位で末尾をゼロ埋めし、各レーンが出力1頂点を全域初期化する。UV を含む出力とパレット余白の帯域費用は、頂点シェーダー経路やストリーム分割と比較する際の測定対象とする。[実機での照合](../verification/current.md#compute-skin)

まず全ビューの深度、影、本描画、速度などの要求を集める。事前カリングには変形を覆う保守的な境界を使い、メインカメラ外の影キャスターを含める。変形結果はモデル空間に置き、ワールド変換を描画時に適用する。共有にはメッシュ版、LOD、スキンバインド、同一の評価結果、モーフ等の追加入力の一致が必要になる。時刻や IK が異なる個体は別に評価する。

| 利用条件 | 選ぶ経路と理由 |
|---|---|
| 同じ変形を複数パス・ビューで使う | コンピュートで一度変形し、必要な頂点属性の和集合を書き出す。小さな仕事はまとめて投入し、静的な UV・色は元のストリームを読む。 |
| 影が別 LOD を使う | 頂点対応が異なるため LOD ごとに計画する。影しか使わない LOD なら位置だけを出力できる。 |
| 小さいモデルを一度だけ描く、またはキャッシュ容量に余裕がない | 同じパレットを読む頂点シェーダー経路を用意する。dispatch、出力書き込み、再読込の費用を含めて端末別に選ぶ。 |
| 速度を描く | 現在と前回描画の変形とワールド変換を使う。初出・テレポート・対応頂点のない LOD 切替では履歴を無効にする。 |

頂点シェーダーをゲームの既定にする判断では、可視な独立ポーズ数と、同じポーズを描く回数（インスタンス数とパス数）を分けて測る。出力用頂点の予算が厳しい単一利用は頂点経路の候補になる。共有が多い条件では単一パスでも Compute が有利になる場合がある。端末別の既定を変えるには、対象 GPU で同じ画質・可視集合の提示間隔とメモリ予算を確認する。[比較条件と実測](../verification/current.md#skin-path-selection)

RenderGraph にパレット転送、コンピュート書き込み、頂点読み取りの範囲と依存を宣言する。最初の比較基準は graphics と同じキューとし、別の compute キューは対象機での対応と同期・所有権移転を確認し、独立した描画との重なりでフレーム全体が短縮した場合に採用する。GPU 完了、記録中の参照、速度用の履歴を含む最後の利用まで出力領域を保持する。[Vulkan の同期とキュー](../guides/vulkan-best-practices.md#synchronization)・[バックエンドの契約](vulkan.md)

個体、ジョブ、イベント、パレット、変形頂点、履歴の容量を準備時に予約する。予算内の通常フレームでは CPU ヒープの確保・再確保・解放と Renderer 起因のネイティブ資源作成・破棄をゼロにする。容量不足時は準備済みで同等の描画が可能な経路へ切り替えるか、必要量を返して明示的に再準備する。ゲーム用イベントの欠落、暗黙のバッファ拡張や GPU 待機は許容しない。保証済み資産の再走査はクック・ロード境界に集約し、同期、容量、寿命の保証は製品構成でも維持する。[定常フレームのメモリ方針](implementation-policy.md#steady-state-memory)・[検証方針](../guides/validation-policy.md)

## 実装順と受け入れ条件

| 順序 | 確認すること |
|---|---|
| 1. 独立クレートと逐次参照評価 | 描画なしで固定入力を再生し、ループ、遷移、ルート移動、イベント順、部分評価と全評価の対象ボーンが一致することを確認する。 |
| 2. CPU 並列評価 | 同じ入力でワーカー数と完了順を変え、ゲーム結果と順序を照合し、姿勢は規定の数値誤差内で比較する。少数の主役と群衆で骨数・ブレンド層・IK を変え、tick の p50/p95、最遅ジョブ、利用側の待ち時間を測る。 |
| 3. GPU の二経路 | CPU の参照変形と頂点・コンピュートの両経路で位置・法線・接線を照合する。複数ビュー、影だけの個体、履歴失効、容量枯渇、複数フレーム同時進行を実機で確認する。 |
| 4. 実機で経路と LOD を選定 | 同じ可視集合・画質で単一パス、深度＋本描画、複数の影を比較する。統合 GPU と独立 GPU でフレーム時間、変形時間、出力バイト数、ピーク常駐量を記録し、CPU メモリ操作とネイティブ資源操作も別々に数える。 |

上記は今後の受け入れ条件である。実測時には対象機・構成・負荷と未確認範囲を[現在の検証状況](../verification/current.md)に記録する。
