# オープンワールド3Dアクションの機能と責務

最初に遊べる範囲として、ひとりのプレイヤーが拠点から見える遺跡まで進み、敵の予備動作を見て回避し、近接攻撃で道を開き、遺物を持ち帰る構成を提案する。往路と帰路を選べる地形にし、帰路では一度離れた区画に入る。これで操作感に加え、遠景と足元の整合、区画の出入り、倒した敵や取得物の保存まで一回のプレイで確かめられる。視点は自由に回せる三人称、初版の対象はシングルプレイと仮定する。

**最初に Sashiko に加える機能は、3D 空間への問い合わせとキャラクター移動、その結果を使うカメラである。** これで一区画の探索と戦闘を作る。次に、地形・当たり判定・配置を区画単位で有効化し、必要な区画だけを常駐させる。ゲームは道を選ぶ理由、敵の行動、アクションの成立条件、世界に残す変化を所有する。

## 現在使えるものと不足するもの

| 系統 | 起点になる実装 | このサンプルで埋める差 |
|---|---|---|
| 実行・入力 | 固定 tick、操作の注入と再生、ゲームパッド、ヘッドレス実行を Survivor が利用する。[ゲーム制作 API](game-engine.md) | 移動方向と視点操作の組み合わせ、押下を先行受付する期間、描画頻度が変わる条件での再現を確認する。 |
| 空間・視点 | Survivor は `sashiko::physics` の3Dボックス掃引で床面上を移動し、運搬箱にインパルスを加える。`CrowdNavigation` は単一の目的地に向かう平面グリッド、`TrackingCamera` は地面を追う正射影カメラである。[空間](../../crates/sashiko/src/space.rs)・[視点](../../crates/sashiko/src/view.rs) | 高低差・上下に重なる通路・厚みのある移動物体を扱う。透視投影に追従・遮蔽回避を組み合わせる。 |
| キャラクター | クリップ、ブレンド、固定 tick のマーカーとルート並進、スキニングがある。標準キャラクター制御の導入条件も既に定義されている。[アニメーション設計](animation.md) | 移動の要求量を衝突で解決し、実移動と表示を揃える。攻撃・回避の許可と中断結果をゲームへ接続する。 |
| 制作・常駐 | シーンに原型・配置 ID・上書きがある。訓練場は版付き素材をロードし、標準 Renderer は候補の分割転送・公開・取消・退役を扱う。[ゲーム制作 API](game-engine.md)・[アセットパイプライン](asset-pipeline.md) | 区画から依存素材を引く索引と、描画・衝突・経路・ゲーム個体の準備状態をまとめるワールド管理が要る。 |
| 表示・音・保存 | 標準描画に加え、HUD の文字・ゲージ、所有者ごとの効果、ミキサー、型付き保存スロットを利用できる。[UI](../../crates/sashiko/src/ui.rs)・[効果](../../crates/sashiko/src/effects.rs)・[音](../../crates/sashiko/src/audio.rs)・[保存](../../crates/sashiko/src/save.rs) | ゲームが通知の意味と保存項目を定める。区画を解放しても差分を保持し、再訪・再起動で同じ配置に適用する。 |

## 機能ごとの実装先

ゲームは新規サンプルとその素材、エンジンは複数のゲームで共有する Rust API・制作ツール・Renderer を指す。表のエンジン欄には既存機能の使い方も含めた。初版で使い切れない機能の採否は、下の受け入れ例で決める。

| 機能 | Sashiko 側で提供するもの | ゲーム側で作るもの |
|---|---|---|
| 操作と時間 | 既存の固定更新と入力注入を使い、視点の相対移動量を tick ごとに一度渡す。軸の反転・感度をホストで適用できるようにする。 | 移動・ジャンプ・回避・攻撃・調べるの割当、入力猶予、メニュー中に受け付ける操作。 |
| 衝突・移動 | 地形・静的メッシュ・動的個体をレイヤーで絞り、レイ、形状の掃引、重なりを問い合わせる。カプセル移動が接地点・法線・実移動量を返し、坂・段差・天井を解決する。 | 加速、旋回、跳躍、空中制御、登れる勾配、落下からの復帰、スタミナ消費。 |
| カメラ・注視 | 透視カメラの旋回と補間、注視点からの球の掃引による壁際の距離補正。視線検査と画面座標への投影を共用する。 | 探索時の距離・仰角、ロックオンの対象選択と切替、ボス戦の構図、揺れの設定。 |
| 戦闘判定 | 固定 tick で範囲内の対象・衝突時刻・接点を取得できるようにする。動く判定形状は前回位置から掃引する。 | 技の予備動作・有効時間・硬直、連携と中断、同一攻撃での重複命中防止、無敵時間、ダメージ・のけぞり・敗北。 |
| 動作と装備表示 | 既存の再生・マーカー・ルート移動差分を使う。必要に応じて共通のアクションスロットと骨への装着を整える。移動差分は衝突解決に一度渡す。 | 技とクリップの対応、足音・判定のマーカー、装備の見た目、遷移条件。壁で止まった回避の移動距離もゲーム状態から読む。 |
| 敵・移動経路 | 視線・近傍検索を共用する。多層地形では歩行可能面と接続を cook し、区画をまたぐ経路、行き止まり、経路の失効を返す。 | 巡回点、発見・追跡・攻撃・帰還の判断、遭遇編成、追跡を打ち切る距離、離れた敵の再出現。 |
| 地形・配置 | 初版は配置メッシュと対応する衝突形状を使う。区画 ID と区画内座標、境界と隣接、安定した配置 ID を表現し、描画・衝突・経路で変換を共有する。 | 道・橋・崖・抜け道・目印、地表材質、植生・建物、敵・収集物・復帰地点の配置。 |
| 読み込みと寿命 | 区画ごとの依存表、距離と予算による先読み、非同期 I/O、取消、参照共有、解放を提供する。準備結果を固定 tick 境界で公開する。 | 常時必要な拠点、遠方から見える目印、移動先の優先指定。準備待ちの境界や高速移動をどう見せるかを決める。 |
| 遠景・照明・描画 | 既存のメッシュ・PBR・影・可視判定・素材転送を使う。距離に応じた LOD 選択、植生のまとめ描画、影の描画距離は実測して拡張する。 | 目印の輪郭が読める遠景素材、植生密度、照明設定、敵の予備動作が背景に埋もれない配色。 |
| 個体・永続化 | 配置 ID とロード中の個体ハンドルを分ける。生成・休止・破棄、区画差分の再適用を共通化し、既存の保存スロットに接続する。 | 開いた扉・取得済み遺物・進行段階・装備の保存項目と版移行、復帰地点、敵の復活条件。 |
| 探索・進行 | 範囲への進入・退出、近傍の候補、イベント購読、編集可能なプロパティを提供する。 | 会話、調べる対象の優先順位、依頼、報酬・所持品、拠点への帰還条件、地図の発見範囲。 |
| UI・音・演出 | 既存の HUD・フォーカス・ミキサー・効果寿命を使う。位置付き音源は距離減衰・左右定位を共通化し、個体消滅時に停止する。 | 体力・スタミナ・目的地の表示、攻撃予告の音・軌跡、環境音、メニュー、入力補助と字幕。 |
| 編集・配布・診断 | 区画単位で編集・cook・依存検査・パッケージ化する。開発時に衝突形状、接地面、区画の要求・公開・退役、待ち時間を観測できるようにする。 | 区画と原型の編集データ、調整用の開始地点、再現入力と期待結果、配布する素材・利用条件。 |

### 区画をまたぐときの契約

たとえば橋から隣の区画へ渡るときは、手前で行き先の区画を要求する。遠景は先に表示できる。足元の衝突と必須配置が準備できた tick から進入を許可し、経路探索にも通行可能な接続を公開する。遅延・読込失敗時は手前の足場を保持する。引き返した後に旧要求が完了しても、要求の世代を照合して二重に個体を生成しない。

離脱時はゲームが配置 ID に対する差分を確定し、エンジンが個体の参照・音・効果を解く。隣接区画と共有する素材を保持し、描画に使った版は最後の利用完了後に回収する。常駐区画数、CPU/GPU 容量、フレームごとの転送量に上限を持たせる。上限では先読みを遅らせ、準備済み容量内の通常フレームで暗黙の拡張や GPU 待ちを起こさない。[フレームメモリ方針](implementation-policy.md#steady-state-memory)・[素材の公開と退役](asset-pipeline.md)

## 実装順と受け入れ例

| 段階 | プレイできる範囲 | 次に進むための確認 |
|---|---|---|
| 1. 常駐一区画 | 坂、低い段差、橋の下、壁際で歩く・跳ぶ・回避する。敵一体の予告を読み、攻撃を当てて遺物を拾う。 | 橋の上下を区別し、カメラが壁に入らない。回避を壁で止めても移動や命中が二重にならない。同じ入力を実画面とヘッドレスで再生し、位置・HP・取得結果を照合する。 |
| 2. 連続する複数区画 | 拠点から二つの道で遺跡を往復する。常駐上限を全区画数より小さくして、解放と再読込を必ず通す。 | 境界で反転し、読込遅延・失敗・再試行を挟んでも床抜けや重複生成がない。再訪とセーブ後の再起動で取得済みの遺物と扉の状態が一致する。リプレイには区画が有効になった tick を記録する。 |
| 3. 規模と制作性 | 別の制作者が既存の原型で寄り道を一つ追加し、配布物から通しで遊ぶ。 | 原本のない環境で追加区画と素材が解決する。対象機材・解像度・移動経路を固定し、通常移動と初回進入のフレーム時間（中央値・p95・最大）、CPU/GPU 常駐量のピーク、転送量、ロード待ちを別々に記録する。 |

広さ・移動速度・表示距離・対象機材は、最初の往復で必要な値を決める。遠端で接地やカメラに精度不足が出たら区画相対座標と原点移動を比較する。専用の高さマップ地形、遠景の統合 LOD、遮蔽カリング、シミュレーションの距離別更新は、同じ経路で負荷や制作上の制約を確認してから採用する。登攀・泳ぎ・乗り物・昼夜天候・手続き生成・協力プレイはそれぞれ移動、保存、同期の要件を変えるため、プレイの目的に含める段階で別途設計する。
